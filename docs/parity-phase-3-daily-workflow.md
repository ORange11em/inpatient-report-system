## ข้อเสนอผู้ประกาศและการเปลี่ยนข้อมูลที่ทำแล้ว

ตามคำสั่งให้เสนอเมื่อบริการยังไม่เก็บผู้ประกาศ: ก่อนทำ `Announcement` ไม่มีผู้เขียน จึงแสดงผู้ประกาศจริงไม่ได้ ข้อเสนอที่ทำตามสิทธิ์แก้backend/API/data modelที่เจ้าของงานอนุญาตแล้วคือเพิ่ม `updated_by` FKแบบnullableและ `publisher_username` snapshotแบบnullable ในmigration `0006_announcement_publisher` ให้บริการตั้งจากผู้เขียนที่ตรวจsessionแล้วทุกPOST/PUT และส่งกลับเป็นช่องอ่านอย่างเดียว ผลหลังทำผู้ดูแลAสร้าง→ผู้ดูแลBแก้ แสดงBตรง `user_update` ของPHP ข่าวเก่าไม่เติมชื่อผู้อพยพหรือผู้อ่าน

ทดสอบ migrationฐานว่าง→head, จำลองข่าวก่อน0006→head, downgrade0005→upgradehead ผ่าน มี guard เพราะ0001เดิมสร้างจากmetadataปัจจุบัน จึงไม่เพิ่มคอลัมน์ซ้ำบนฐานใหม่ **ยังไม่ได้อัปเกรดฐานใช้งานหรือฐานเดิมของผู้ใช้** ก่อนนำโค้ดนี้ไปใช้กับฐานเดิมต้องรัน `alembic upgrade head` ในสภาพแวดล้อมที่กำหนด

เพิ่ม GET `/entries/{id}/events` ตรวจสิทธิ์อ่านหอเหมือนรายการเดิม แสดงเหตุการณ์ใน shared `EntryActivity` ทั้งฟอร์มและdialog ไม่แก้คำขอหรือสูตรสร้าง/แก้/ยืนยัน/ส่งกลับที่มีอยู่ เพิ่มสถานะโหลด/ผิดพลาด/ลองใหม่ ใช้คีย์บอร์ดและtokensเดิม วันที่ผ่าน utilกลางเป็นพ.ศ. ไม่แตะผลพิมพ์/Excel
