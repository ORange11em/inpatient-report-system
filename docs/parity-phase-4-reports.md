# เฟส 4 — ผลเทียบรายงาน 15 แบบ

ตรวจวันที่ 20 พฤศจิกายน 2569 ใช้ [P1 v1](parity-fixtures-phase-1.md) และชุดเสริมที่แยกเดือนออกจาก P1 ปิดช่องว่างที่สั่งทั้ง4จุดแล้ว มีผลตรวจครบ15แบบบนจอ ใบพิมพ์ และExcel XMLของระบบใหม่ โดยเทียบ PHPแต่ละช่องทางแยกกัน **ยังไม่รับรองว่าเหมือนPHPทุกกรณี**: แถวรวมTurnoverใช้SQLเดิมที่ไม่กำหนดแถวเตียงแน่นอน และไฟล์พิมพ์Productivityเดิมล้มก่อนมีผลลัพธ์สมบูรณ์ รายละเอียดและตัวเลขอยู่ด้านล่าง

คำสั่งล่าสุดอนุญาตแก้สูตร/backend/APIตามความจำเป็นของเฟสนี้แล้ว ใช้เกณฑ์D01เตียงท้ายเดือน, D03ขอบเขตหอ และD08ไม่มีตัวหารเป็นnullตามที่อนุมัติไว้ ส่วนD02คำตอบเก่าที่ให้ใช้สูตรใบพิมพ์ร่วมทุกช่องทางถูกแทนด้วยคำสั่งให้ **จอเทียบจอ พิมพ์เทียบพิมพ์ ExcelเทียบExcel** จึงคงน้ำหนักแต่ละช่องทางตามซอร์ส ไม่ขอให้เจ้าของงานเลือกสูตรซ้ำ

GROUP BY ward ORDER BY idate,wage_type_id` ไม่ได้เลือกเตียงท้ายงวดอย่างรับรองได้ `ONLY_FULL_GROUP_BY`จะไม่ยอมรับคำค้นนี้ ฐานทดสอบMyISAM/SQL modeว่างเลือก20+10=30 ส่วนใหม่ท้ายงวด25+10=35 ผล.23/.20ต่างเพราะฐาน ไม่ใช่การปัดหรือสิทธิ์ ยังไม่มีข้อมูลฐานเก่าจริงที่จะรับรองผลย้อนหลังแถวรวมนี้ ไม่เปลี่ยนสูตรใหม่ให้ผูกกับลำดับแถวที่ไม่แน่นอน
- **สถานะmonthly:** `report_month.php:229–242` และ`report/report_month_r.php:118–131`กรองวันที่ด้วยสถานะ แต่ต่อ`AND data_all.i_status=...` หลัง`ORDER BY`ในคำค้นเวรย่อย จึงรวมเวรรอยืนยันในวันที่มีเวรยืนยันด้วย ระบบใหม่ทำตามจุดใช้งานเดียวกันโดยเลือกวันตามสถานะแล้วนำทุกเวรของวันนั้นมารวม กรณีP1 confirmed ให้44%/ให้การพยาบาล14; จอ, พิมพ์, XML ใหม่ได้ค่าเดียวกัน ไม่มีการเปลี่ยนข้อมูลหรือสถานะเวร
- **การปัด:** backendเปลี่ยนจากPython roundแบบhalf-evenเป็นPHP half-up เช่น13.125→13.13, 2.675→2.68; ค่าเฉลี่ยPTในmonthlyเก็บสามตำแหน่ง ตัวเลขอัตราบนรายงานแสดงสองตำแหน่งตามPHP XMLเก็บNumberเช่น11.5 ส่วนจอ/พิมพ์อาจจัดเป็น11.500 ค่าตัวเลขเดียวกัน ไม่ใช้สตริงจัดรูปแบบคำนวณต่อ
- **สิทธิ์:** ค่า12กับ18ในรวมทุกตึกเป็นคนละขอบเขตหอ ไม่ใช่สูตรผิด บัญชีreaderอ่านAอย่างเดียว ส่วนmultiอ่านA+B ผู้ที่ไม่มีสิทธิ์Bเรียกตรงได้403ทั้งreportและข้อมูลช่องทางเพิ่มเติม มีการดาวน์โหลดXMLและตรวจprint DOMของทั้งสองบัญชีแยกจริง

การแก้ทั้งหมดจำกัดการอ่าน/คำนวณ/แสดงรายงาน ไม่เปลี่ยนข้อมูลที่บันทึก สูตรคงเหลือของฟอร์ม ขั้นตอนยืนยัน/ส่งกลับ สิทธิ์เขียน data model หรือเครื่องมือนำเข้า

## 4. วิธีและขอบเขตหลักฐานรอบนี้

**PHPจริงแบบแยกฐาน:** ใช้PHP8.2กับMariaDB10.4.32ที่มีในเครื่อง สร้างdatadirใหม่ในTEMP ฟัง127.0.0.1พอร์ตสุ่ม ใช้เฉพาะCREATE TABLEจากdumpและตัวเลขสมมติ ไม่อ่านINSERTข้อมูลจริง ไม่เชื่อม`connect.php`เดิม คัดลอกไฟล์รายงานไปTEMPและตรวจbyteเท่าต้นฉบับทุกครั้ง เปลี่ยนเฉพาะconnection/session/header/menuในสำเนาทดสอบ

ความเข้ากันได้ที่ประกาศชัด: ใส่shim `split→preg_split`, `mysql_fetch_row→mysqli fetch_row` และนิยามbarewordที่PHP5แปลงเป็น0ในเลขคณิตเพื่อให้PHP8ไม่หยุดก่อนถึงสูตร ไม่เปลี่ยนนิพจน์ SQLหรือคำนวณในไฟล์รายงาน ผลนี้ไม่ใช่การทดสอบระบบPHPเต็มชุดด้วยบัญชี/ฐานจริง การเก็บตัวแปรผู้ประกาศหรือsessionจากเฟส3ไม่ใช่หลักฐานรอบนี้

มี**61การเรียก PHP**: 45กรณีหลัก15×3 และ16กรณีเสริม **56รันจบ / 5ล้มตามข้อจำกัดที่บันทึก** (Productivityพิมพ์/Excel2, เดือนที่ไม่มีจำหน่ายบนPHP8สามช่องทาง3) และมี**24กรณีนิพจน์Productivityที่ดึงจากซอร์สแล้วรันPHPแยก** ไม่มีการแก้ต้นฉบับเพื่อทำให้ตัวเลขดูผ่าน
