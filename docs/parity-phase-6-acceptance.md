# เฟส 6 — ตรวจรับระบบรายงานผู้ป่วยใน

วันที่ตรวจรอบนี้ 20 พฤศจิกายน 2569 (2026-11-20) · รุ่น new-system ใน workspace · ใช้เฉพาะข้อมูลสมมติ P1/fixtures และ PostgreSQL แยกสำหรับทดสอบ · ไม่มีการอ่านหรือเขียนฐานข้อมูลใช้งานจริง

## ขอบเขตและระดับหลักฐาน

ตรวจเริ่มจากหน้าใช้งานจริงของระบบใหม่ผ่าน browser และ API บน PostgreSQL ชั่วคราว ครอบคลุมบัญชีประจำหอ ผู้ดูรายงาน ผู้ดูหลายหอ ผู้ดูแล และ auditor ตาม fixtures; ใช้ P1 เดียวกับที่บันทึกใน [รายการตรวจ PHP เทียบระบบใหม่](../INPATIENT_PARITY_TH.md), [ผลรายงานเฟส 4](parity-phase-4-reports.md) และ [ชุดตัวเลข P1](parity-fixtures-phase-1.md)

ระบบ PHP/MySQL เดิมเปิดรันซ้ำในรอบตรวจรับนี้ไม่ได้ เพราะไม่มี PHP/MySQL/MariaDB ในสภาพแวดล้อม จึงแยกผล **รันจริงกับระบบใหม่รอบนี้** ออกจาก **ผล PHP/ซอร์สที่มีบันทึกเดิม** อย่างชัดเจน ตารางรายงานด้านล่างสถานะผ่านหมายถึง new-system ผ่าน fixture และมีหลักฐานเปรียบเทียบ PHP ที่ระบุไว้ในผลเฟส 4; ไม่ใช่การรัน PHP พร้อมกันในรอบนี้ จุดที่หลักฐาน PHP เดิมขัดแย้ง/ไม่กำหนดผลยังเป็น “ยังตรวจไม่ได้”

## ความพร้อมและตัวขวางการเปลี่ยนระบบ

- วงจรบันทึกเวรและขอบเขตสิทธิ์ที่ทดสอบด้วยผู้ใช้สมมติ พร้อมสำหรับการตรวจ UAT ในฐานทดสอบ; รายงาน 15 ชนิดสร้าง/แสดง/พิมพ์/ส่งออกผ่าน fixtures ของ new-system และมีผล PHP comparison ก่อนหน้าประกอบในกรณีที่ระบุว่า “ผ่าน”
- **ยังรับรองการเปลี่ยนแทนระบบเดิมทั้งโรงพยาบาลไม่ได้**: รอบนี้ไม่มี PHP/MySQL ให้รันเทียบสด; Productivity print เดิมล้มก่อนสร้างผลเต็ม, แถวรวม turnover ของ PHP ผูกฐานเตียงไม่แน่นอน และสูตรรวม R08 เมื่อเตียงแปรผันยังไม่รับรอง (หลักฐานเก่าพิสูจน์กรณีเตียงคงที่เท่านั้น)
- ยังมีช่องว่าง UI จากเฟส 7: F01 มีศัพท์ “API” ในตัวช่วยช่องวันที่, F03 contrast ช่องเข้าสู่ระบบ, F04 ความสูงปุ่ม 42px; F05 แจ้งเตือนบังปุ่มบันทึกปิดได้ในการทดสอบ browser แต่ยังไม่ใช่อุปกรณ์จริง
- การย้ายข้อมูลย้อนหลังยังไม่ครบ: มีเพียง `data_all` และ `data_confirm`; ไม่มี importer สำหรับ `data_split_patient`, `pressure`, `readmit`, `tb_news` และไม่มี operational rows จริงใน dump ที่ให้มา จึงยังเปิดรายงานจากข้อมูลย้อนหลังจริงหรือยืนยันยอดก่อน–หลังจริงไม่ได้
- ปลายทางโปรแกรมความพึงพอใจภายนอกไม่มีใน workspace; ตรวจได้เพียงการสร้างทางไปตาม config ไม่ถึงผลในระบบภายนอก
- ลินต์ standalone ใช้ไม่ได้จาก tooling ปัจจุบัน; build และชุดทดสอบผ่าน ไม่ได้เพิ่ม dependency ในเฟสตรวจรับ

ข้อสรุป: ใช้ทดแทนเพื่อทดลองงานประจำวันและรายงานบนข้อมูลทดสอบ/สภาพแวดล้อมที่ได้รับอนุมัติได้ แต่ **ยังไม่พร้อม cutover หรือทิ้งระบบ PHP/MySQL** จนกว่าจะทดสอบฐาน/ผล PHP จริงในสภาพแวดล้อมที่เข้าถึงได้ ปิดเครื่องมือนำเข้าตารางเสริม และทำ reconciliation ข้อมูลจริงที่ได้รับอนุญาต
