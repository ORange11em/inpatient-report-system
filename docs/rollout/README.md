# ตรวจสำเนาและซ้อมก่อนย้ายระบบ

วันที่ 23 พฤศจิกายน 2569 · เฉพาะเครื่องทดสอบแยก · ยังไม่อนุญาตนำเข้าฐานจริงหรือสลับระบบ

## ส่งให้ฝ่ายไอทีตรวจสำเนา

ใช้ [source-inventory.sql](source-inventory.sql) ซึ่งมีเฉพาะ SELECT กับฐานสำเนาที่ได้รับอนุญาต ให้ผู้ดูแลตรวจชื่อตาราง/คอลัมน์กับสำเนาก่อนรัน ยังไม่ได้รันไฟล์นี้กับ MySQL ของโรงพยาบาล ผลที่ทราบปัจจุบันมาจากการอ่าน dump ในโครงการเท่านั้น ไม่ใช่จำนวนบนเซิร์ฟเวอร์จริง

จาก PowerShell ใช้ client ที่ติดตั้งอยู่แล้ว ระบุค่าฐานสำเนาเอง และให้ `--password` ถามรหัสผ่าน ห้ามใส่รหัสผ่านต่อท้ายคำสั่ง:

```powershell
# เปลี่ยน placeholder และตำแหน่งไฟล์ให้ตรงพื้นที่จำกัดสิทธิ์ของโรงพยาบาล
# mysql SOURCE ใช้ path ที่ไม่มีช่องว่าง; ทำสำเนา SQL ไปยังพื้นที่นั้นก่อน
mysql --host=COPY_HOST --port=3306 --user=READ_ONLY_USER --password --database=COPY_DB --default-character-set=utf8 --batch --execute="SOURCE D:/restricted-staging/source-inventory.sql" --result-file="D:/restricted-staging/inventory-result.tsv"
Get-FileHash -Algorithm SHA256 -LiteralPath 'D:/restricted-staging/inventory-result.tsv'
```

ผลต้องมีจำนวนทั้ง 6 ตาราง วันแรก/สุดท้าย (ค่าว่างไม่ใช่วันเริ่มต้น), วันที่ศูนย์/ขาด, เดือน `month1`, เวลายืนยัน, รหัสหอ/เวร และข้อยกเว้นคีย์ซ้ำ/จับคู่ไม่ได้ ตารางเดิมเป็น MyISAM จึงต้องใช้สำเนาที่คงที่หรือหยุดการเขียนตามแผนของฝ่ายไอทีก่อนส่งออก; transaction snapshot อย่างเดียวไม่ทำให้ตารางเหล่านี้สอดคล้องกัน ห้ามถือวันที่สร้าง dump เป็นช่วงข้อมูล

รับไฟล์และผลตรวจผ่านพื้นที่จำกัดสิทธิ์ของโรงพยาบาลเท่านั้น ไม่ส่งบัญชี รหัสผ่าน รายละเอียดข่าว หรือข้อมูลระบุตัวผู้ป่วยลงแชต/ซอร์ส/บันทึกสาธารณะ ผลแบบแยกวัน/หอต้องคงอยู่ในพื้นที่ดังกล่าว ให้ฝ่ายไอทีอนุมัติเฉพาะผลรวมที่จะนำมาแนบรายงานนี้

## ไฟล์ที่ยังขาดและข้อตกลงส่งออก

สำเนาปัจจุบัน `inpatient/db/db_inpatient.sql` มีโครงสร้างแต่ไม่มีแถวใน `data_all`, `data_confirm`, `data_split_patient`, `pressure`, `readmit`, `tb_news` มีข้อมูลอ้างอิงหอ 19 แถว เวร 3 แถว (1 ดึก/2 เช้า/3 บ่าย) เดือน 12 แถว ไม่ย้ายตารางบัญชีหรือรหัสผ่าน

ขอให้ฝ่ายไอทีจัดเตรียม manifest ระบุรหัสชุด/ผู้ส่งออก/เวลาสำเนา/เขตเวลา/ฐานสำเนาที่ใช้/ช่วงข้อมูลที่อนุญาต/เวอร์ชัน schema/encoding/จำนวนแถวและช่วงวันที่รายตาราง/SHA-256 รายไฟล์/วิธีแทน NULL และช่องว่าง ย้ายทุกแถวที่ได้รับอนุญาตตาม manifest ไม่กำหนด cutoff เอง

| ไฟล์ | รูปแบบ/ความหมาย | สถานะ |
|---|---|---|
| `data_all.csv` | normalized UTF-8 ตาม `backend/docs/templates/data_all_template.csv`; `on_pt→pt_on` และรูปแบบเดียวกัน; วัน ค.ศ. ISO; รหัสหอ/เวรเดิม; ตัวนับ NULL จะถูกปฏิเสธพร้อมเหตุผล ห้ามเติม 0 | ตัวนำเข้าเดิมใช้ได้; รอไฟล์ที่มีข้อมูล |
| `data_confirm.csv` | `ward,idate,wage_type_id,cdate,cuser`; เหตุการณ์แยกจากสถานะ; ห้ามตัดแถวซ้ำหรือเรียงใหม่โดยไม่ตกลง เพราะ hash รักษาลำดับ occurrence | ตัวนำเข้าเดิมใช้ได้; รอไฟล์ที่มีข้อมูล |
| `account-map.csv` | `legacy_account_id,target_username` เฉพาะผู้ใช้ใหม่ที่สร้างไว้และใช้งานได้แล้ว; ไม่ส่ง `account`/`pass_login` | รอเจ้าของบัญชียืนยัน; ขาดผู้ใช้/เวลาเก็บเป็นไม่มีข้อมูล |
| `data_split_patient` | เสนอ CSV คอลัมน์ตาม schema: หอ+วัน, 13 สาขา × `_n`/`_s`; จับคู่เวรบ่ายเดิม 3 โดยไม่ใช้ PK ใหม่แทน | ยังไม่ตกลงรูปแบบ NULL/ว่างและยังไม่มีตัวนำเข้า |
| `pressure` | เสนอ CSV หอ+วัน, `do_pressure,risk_pressure`; ไม่มีแถวต่างจากแถว 0/0 และ NULL | ยังไม่มีตัวนำเข้า |
| `readmit` | เสนอ CSV `ward,month1,idate,readmit_amount,discharge_amount`; เดือนรายงานมาจาก `month1` วันแก้เดิมจาก `idate` | ยังไม่มีตัวนำเข้า; ต้องรักษาวันแก้เป็น provenance |
| `tb_news` | เสนอ CSV ตาม schema `id,title_news,detail_news,status_news,date_news,time_news,user_update`; จับคู่ผู้แก้ล่าสุดตามหลักฐาน ไม่กล่าวอ้างเป็นผู้ประกาศครั้งแรก | ยังไม่มีตัวนำเข้า; ให้โรงพยาบาลตรวจเนื้อหาก่อนส่ง |
| หอ/เวร/เตียง | รหัสและชื่ออ้างอิง พร้อมแหล่งประวัติความจุและวันที่มีผลถ้ามี | ห้ามสร้างประวัติเตียงจากจำนวนปัจจุบัน |

สำหรับ 4 ตารางเสริม รูปแบบยังเป็นข้อเสนอ ให้ฝ่ายไอทีรับรองก่อนพัฒนาตัวอ่าน ใช้ `\N` แทน NULL และ empty string แยกต่างหากเป็นข้อเสนอที่ยังไม่อนุมัติ ตัวอ่าน 2 ตัวเดิมใช้กติกาค่าว่างตามเอกสารเดิมและห้ามเปลี่ยนกติกาเอง

## วิธีซ้อมซ้ำด้วยข้อมูลสมมติ

ใช้ PostgreSQL binaries ที่มีในเครื่อง ไม่ติดตั้ง dependency เพิ่ม:

```powershell
cd 'C:/Users/Ult_Orange/Desktop/โฟลเดอร์ใหม่/new-system/backend'
.\.venv\Scripts\python.exe tests/run_rollout_rehearsal.py --pg-bin "$env:TEMP/inpatient-parity-phase3-pg-gpyoql0w/pgsql/bin"
```

สคริปต์สร้าง cluster ใหม่ใน TEMP บน loopback/พอร์ตสุ่ม ไม่ใช้ DATABASE_URL ของผู้เรียก ไม่แตะฐานพัฒนาเดิม ใช้ตัวนำเข้าและสูตรเดิมโดยไม่แก้ไข สำรองก่อนนำเข้า, dry-run, apply, reconciliation, รันไฟล์เดิมซ้ำ, เทียบทุกตัวนับ/สถานะ/จำนวนค่าว่างแยกหอ วัน เวร เดือน, ตรวจ HTTP รายงานตามสิทธิ์, สำรองหลังนำเข้าและกู้ลงฐานใหม่, เปิดรายงานผ่าน HTTP จากฐานกู้คืน และกู้ snapshot ก่อนนำเข้าไปยังฐาน rollback ใหม่ ปิดเฉพาะบริการที่สร้างเองใน finally

ทดสอบหน้าเว็บจริงเพิ่มได้ด้วยแพ็กเกจ Playwright ที่มีอยู่แล้วในเครื่อง (ไม่ติดตั้งลงโครงการ):

```powershell
$env:PLAYWRIGHT_MODULE = 'C:/Users/Ult_Orange/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright'
.\.venv\Scripts\python.exe tests/run_rollout_rehearsal.py --pg-bin "$env:TEMP/inpatient-parity-phase3-pg-gpyoql0w/pgsql/bin" --with-browser
.\.venv\Scripts\python.exe tests/check_rollout_inventory_sql.py --mysql-bin C:/xampp/mysql/bin
```

`--with-browser` ต้องมีหน้าเว็บทดสอบที่ `http://localhost:3000` หรือระบุ `--ui-base-url` เป็น loopback แยก คำขอข้อมูลจาก browser ถูกส่งไปบริการฐานทดสอบที่สคริปต์สร้างเท่านั้น ไม่ใช้ข้อมูลจำลองตอบแทนบริการจริง ทดสอบ 2 บัญชี × 4 ขนาดจอทั้งก่อนและหลังกู้คืน และตรวจยอด XML/ขอบเขตใบพิมพ์ ส่วนคำสั่งตรวจ SQL สร้าง MariaDB ใหม่ใน TEMP คัดลอกเฉพาะ schema 8 ตาราง ไม่คัดลอกบัญชีหรือข้อมูลต้นทาง ใช้ตรวจคำสั่ง SELECT กับตารางว่าง ไม่ใช่ตรวจฐานโรงพยาบาล

ผลรวมที่เปิดเผยได้อยู่ใน [rehearsal-result.json](rehearsal-result.json) เมื่อรันสำเร็จ ไม่มีรหัสผ่านหรือ connection string ในผล ไฟล์สำรองและการตั้งค่าลับอยู่เฉพาะ TEMP นอกซอร์ส สคริปต์นี้พิสูจน์เฉพาะข้อมูลสมมติ ไม่ใช่หลักฐานกู้คืนเครื่องจริงหรือการย้อนรายการที่กรอกหลังสลับ

ยังไม่พร้อมเปิดจริงจนกว่าข้อมูลตรวจสอบได้ ความต่างรายงานได้รับการรับรอง กู้คืนผ่านบนสภาพแวดล้อมเป้าหมาย และทั้งพยาบาล เจ้าของรายงาน และฝ่ายไอทีโรงพยาบาลลงนามรับรอง การสลับระบบต้องมีคำสั่งอนุมัติแยกอีกครั้ง
