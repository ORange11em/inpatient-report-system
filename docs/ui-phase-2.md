# เฟส 2 — App Shell และหน้าแรก

อัปเดต 19 พฤศจิกายน 2569 พัฒนาเฉพาะหัวข้อ B/C1 และกติการ่วม A/D/E ใน spec ยังไม่เริ่มเฟส 3–7

## ขอบเขตและสิ่งที่อนุญาต

ผู้ใช้อนุญาตว่า **“อนุญาตเพิ่มคำขออ่านจากบริการเดิมสำหรับหน้าแรกและเลือกหอผู้ป่วย”** จึงเพิ่ม GET ที่ใช้แสดงผลด้านล่าง ไม่มี endpoint ใหม่ ไม่มีการเปลี่ยน backend, data model, AuthProvider, routing, สูตรรายงานเดิม หรือ dependency

คำขอข่าวยังใช้ POST/PUT/DELETE เดิม พร้อม `title/body/published`, `version` ใน query และ CSRF ไม่ส่ง author/pinned เพิ่ม การยืนยันและการบันทึกฟอร์มเดิมไม่เปลี่ยน

ไม่พบ `docs/screenshots/01-home.png` ใน workspace มีเพียงภาพเดิม 6 ภาพที่บันทึกไว้ใน Audit จึงใช้ spec และโครงสร้าง/ข้อมูลจากซอร์สเดิม และยังไม่ได้เทียบหน้าแรกกับภาพที่ขาดนั้น

ทุกโหมดใช้เมนูเดิม 7 ปลายทางและชื่อไทยตาม A5 เมนูประวัติแยก active กับ `/history?status=unconfirmed` ตัวนับรอยืนยันมาจากบริการเดิมทุกช่วงวันที่ตามสิทธิ์ ซ่อนเมื่อ 0 และแสดง `99+` เมื่อเกิน 99

- การย่อ sidebar จำใน `localStorage`; ไม่กระทบโหมด rail/tablet และมือถือ
- Drawer ใช้ shared component มี overlay, Esc, focus trap, คืนโฟกัส และ scroll lock; ปิดเมื่อเลือกเมนูหรือขยาย viewport ถึง 768px
- Header มีชื่อหน้าจริง, breadcrumb บนจอที่ไม่ใช่มือถือ, วัน พ.ศ. ผ่าน util กลาง และตัวเลือกหอที่บัญชีมีสิทธิ์
- ตัวเลือกหอจำข้ามการเปิดหน้า ค่าเริ่มต้นหน้าบันทึกเรียงตาม deep link เดิม → หอที่จำไว้และยังมีสิทธิ์ → หอแรก ส่วนตัวชี้วัดใช้หอที่จำไว้ → หอแรก ไม่มีการสั่งโหลดหรือเขียนทับฟอร์มที่เปิดค้างอยู่เมื่อเปลี่ยน header
- โปรไฟล์เป็น dialog แสดงชื่อบัญชี/สิทธิ์ที่ทราบ/หอปัจจุบัน ใช้ `is_admin` แสดงผู้ดูแลระบบ ส่วนบัญชีอื่นใช้ข้อความกลาง ไม่แต่งบทบาทหัวหน้าหอ/พยาบาล
- สถานะออนไลน์/กำลังซิงก์/ขาดการเชื่อมต่ออิง browser online และผล GET รายชื่อหอ/ตัวนับรอยืนยัน ปุ่มลองใหม่ทำคำขออ่านสองส่วนนี้ซ้ำ รายละเอียดบอกชัดว่าเวลาตรวจสำเร็จล่าสุดไม่ใช่เวลาปรับปรุงข้อมูลทุกส่วน
- บนมือถือสถานะเป็นไอคอนพร้อมชื่อที่โปรแกรมอ่านหน้าจออ่านได้ และกดดูข้อความรายละเอียดได้

## หน้าแรกและข้อมูลที่ใช้

| ข้อมูล | แหล่งเดิม | การแสดงผล |
| --- | --- | --- |
| หอและสิทธิ์เขียน | `GET /wards` | แสดงเฉพาะหอที่บริการอนุญาต ใช้ `can_write` กับปุ่มบันทึก |
| ชื่อและลำดับเวร | `GET /shifts?include_inactive=true` | สถานะใช้เวรที่เปิดและรหัส legacy 1/2/3 ไม่สมมติว่า primary key เท่ากับรหัสเวร |
| สถานะวันนี้/ความครบถ้วนทุกหอ | `GET /reports/daily?service_date=YYYY-MM-DD` | บริการจำกัดสิทธิ์; ไม่มีรายการ = ยังไม่บันทึก, `unconfirmed` = รอยืนยัน, `confirmed` = ยืนยันแล้ว |
| KPI/แนวโน้ม/เทียบเมื่อวาน | รายงานรายวันเดิม 7 วัน รวมวันนี้; 6 วันก่อนหน้าส่ง `ward_id` ของหอที่เลือก | ใช้ข้อมูลหอที่เลือก ไม่รวมข้อมูลคนละหอ |
| ข่าว | `GET /news` เดิม | วันที่ พ.ศ., หัวข้อ/เนื้อหา/ฉบับร่างตามข้อมูลจริง; เพิ่ม/แก้ไขผ่าน shared dialog |

การคำนวณใหม่มีไว้แสดงผลเท่านั้นใน `lib/dashboard.mjs` ไม่ถูกส่งกลับบริการ ไม่ถูกนำไปแทนสูตรรายงานหรือยอดยกมา:

- คงเหลือ PT ใช้เวรล่าสุดที่มีรายการ: `pt_on + pt_in + pt_move - pt_home - pt_move_b - pt_send - pt_dead - pt_non_voluntary` ไม่บวก A&D และไม่รวมยอดยกมาซ้ำทุกเวร
- รับและจำหน่ายรวมรายการของวันนี้ถึงเวรล่าสุด โดยแสดงว่าเป็นยอด PT แยกจาก NB
- เตียงว่าง = จำนวนเตียงของเวรล่าสุด − ยอดคงเหลือ; ส่วนต่างใช้หน่วยเตียง
- ร้อยละครองเตียง = ยอดคงเหลือ ÷ จำนวนเตียงของเวรล่าสุด × 100 บนจอมีคำอธิบายว่าช่วงคำนวณต่างจากรายงานรายเดือน ไม่เปลี่ยนสูตรชั่วคราว/ตัวหาร/complete ของรายงานเดิม
- เปรียบเทียบเมื่อวานถึงเวรเดียวกันเท่านั้น ถ้าเวรนั้นไม่มีเมื่อวาน แสดงว่ายังไม่มีข้อมูลเปรียบเทียบ
- ไม่มีรายการหรือไม่มีฐานเตียง แสดง `—` แทนศูนย์ กราฟเว้นช่วงวันที่ไม่มีข้อมูล ไม่สร้างค่าศูนย์ขึ้นแทน
- ความครบถ้วนนับหอที่ยืนยันครบทุกเวรที่เปิดใช้งาน ไม่ถือว่ามีรายการหนึ่งเวรแล้วส่งครบทั้งหอ รายชื่อหอที่ขาดเปิดดูได้

เปลี่ยนหอแล้วแสดง loading ก่อนผลใหม่ และละทิ้งผลอ่านที่ตอบช้าของหอเก่า หากอ่านรายงานไม่สำเร็จแสดง error/retry แทนสถานะ “ยังไม่บันทึก” ข่าวมีสถานะโหลด/ว่าง/ผิดพลาดแยกจากรายงาน

## ผลทดสอบ

ใช้ Edge แบบ headless ผ่าน Playwright ที่มีใน runtime ของเครื่อง ไม่ติดตั้งแพ็กเกจในโปรเจกต์ ทุกคำขอบริการในการตรวจ browser ถูกแทนด้วยข้อมูลสมมติ ไม่อ่านหรือบันทึกข้อมูลผู้ป่วยจริง ผลนี้ตรวจการทำงานหน้าจอและสัญญาคำขอ ไม่ใช่ผลเชื่อม backend จริง

- หน้า `/`: 360/767/768/1023/1024/1440px ผ่าน ไม่มี horizontal scroll ทั้งหน้า; rail/sidebar วัดได้ 80/248px ตามตาราง
- หน้า `/entries`, `/history`, `/history?status=unconfirmed`, `/indicators`, `/reports`, `/occupancy`: ตรวจ shell และความกว้างเริ่มต้นที่ 360/768/1024/1440px รวม 24 กรณี ผ่าน ไม่ถือเป็น QA ครบทุก flow ของหน้าในเฟสถัดไป
- ย่อ/ขยายและ reload จำสถานะ; drawer focus trap/Esc/คืนโฟกัส/scroll lock/ปิดเมื่อถึง 768px; มือถือเปิดโปรไฟล์และออกจากระบบได้
- เลือกหอแล้วผลหน้าแรกเปลี่ยน; หน้าบันทึก/ตัวชี้วัดรับค่าเริ่มต้นจากหอที่จำไว้ และลิงก์เปิดเวรระบุหอไว้มาก่อน preference
- ตัวนับเป็น 0 ซ่อน badge; บัญชีไม่ใช่ผู้ดูแลไม่เห็นเพิ่มข่าว; ข่าวว่างมีคำอธิบาย; รายงานว่างไม่แสดง KPI เป็นศูนย์
- อ่านรายงานช้าแสดง skeleton; ล้มเหลวมี error/retry; pending-count ล้มเหลวแสดงขาดการเชื่อมต่อและลองใหม่แล้วกลับออนไลน์
- ข่าว POST/PUT/DELETE คงฟิลด์เดิมและ CSRF; PUT/DELETE ใช้ query version เดิม การ logout ยังใช้คำขอเดิม ไม่มี JavaScript page error ระหว่างตรวจ
- `npm run test:ui`: ผ่าน **15/15** รวมเทสต์วันที่ไทยเดิม 9 และเทสต์หน้าแรก 6
- `npm run build`: ผ่าน ไม่มี route ใหม่ในเฟสนี้ หน้า `/dev/ui-kit` และ guard เฉพาะ dev จากเฟส 1 ไม่เปลี่ยน
- `npm run lint`: รันไม่สำเร็จเพราะ package.json เดิมไม่มี script `lint`
- `npx --no-install tsc --noEmit`: รันไม่สำเร็จเพราะไม่มี TypeScript compiler/การตั้งค่า typecheck เดิม ใช้ `--no-install` เพื่อไม่ดาวน์โหลดเครื่องมือเพิ่มเอง ไม่อ้างว่า build แทน lint/typecheck ครบแล้ว
- ตรวจ SHA-256 กับ snapshot ก่อนเฟส 2: ไฟล์เดิม 197 ไฟล์ มีการแก้ 6 ไฟล์ frontend ตามตารางและ `docs/ui-progress.md` รวม 7 ไฟล์; อีก 190 ไฟล์ตรงกัน ไม่ลบไฟล์ ไม่มี backend/AuthProvider/lib API/census/package/lock/config เปลี่ยน ตรวจลิงก์ในเอกสารที่แก้แล้วไม่พบลิงก์ไฟล์เสีย

## เรื่องที่ยังต้องตัดสินใจ

1. **Q03/Q04:** ช่วงเวลาเวร/ความหมายวันที่ข้ามคืนและเวลาตัดรอบจริง ยังไม่แสดงชั่วโมง สถานะเลยกำหนด หรือเวลาผ่อนผัน
2. **Q02/Q11:** ชื่อบทบาทที่เป็นทางการและข้อมูลผู้บันทึก/ผู้ยืนยัน/เวลายืนยัน/ผู้โพสต์/ปักหมุด บริการยังไม่ส่งในข้อมูลที่หน้านี้ใช้ จึงไม่แต่งจากบัญชีปัจจุบันหรือ updated_at
3. **Q10:** หน้าแรกระบุความหมาย KPI บนจอเป็นยอด PT ถึงเวรล่าสุดและเทียบเวรเดียวกัน หากต้องการรวม NB หรือช่วงอื่นต้องตกลงแยก; การอนุญาตอ่านครั้งนี้ไม่ขยายไปเปลี่ยนจังหวะโหลดของหน้าประวัติ/ฟอร์ม/รายงานเฟสถัดไป
4. **Q14/Q16:** โปรไฟล์ใช้ข้อมูลจริงใน dialog และยังไม่เพิ่มหน้าโปรไฟล์; login คงเดิม การเปลี่ยนระบบซิงก์ทุกหน้า/ฟอร์มที่เปิดค้าง/ขอบเขต login ต้องกำหนดเพิ่มเติมก่อนทำ
5. ภาพอ้างอิง `01-home.png` ยังไม่อยู่ใน workspace; ยังไม่ได้ตรวจ iPhone จริง, zoom 200%, Lighthouse หรือทุก flow ทั้งระบบ ซึ่งอยู่ในเฟส 7
