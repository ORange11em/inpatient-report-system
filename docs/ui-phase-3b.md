# เฟส 3b — การกรอก ตรวจทาน และค่าค้าง

อัปเดต 19 พฤศจิกายน 2569 ทำเฉพาะ `/entries` และส่วนเชื่อมข้อมูลที่เกี่ยวข้อง ไม่เริ่มเฟส 4–7 คำสั่งเฟส 3b อนุญาตพฤติกรรมฝั่งหน้าจอใน Q12 แล้ว โดยยังคง business rules, validation, สัญญาคำขอ และข้อมูลส่งเดิม

## การกรอกและแถบบันทึก

- Focus ช่องตัวเลขแล้วเลือกค่าทั้งช่อง; Tab/Enter ไปช่องถัดไป และ Shift+Tab/Shift+Enter ย้อนกลับตามลำดับอ่าน รวมช่องใน accordion ที่ยังปิด เมื่อถึงช่องสุดท้าย Enter พาไปปุ่มบันทึกโดยไม่ส่งเอง
- Ctrl/Cmd+S เรียก submit ของฟอร์มเดิม ผ่าน required/min/max/step และคำยืนยันเดิม ไม่ส่งซ้ำเมื่อกดค้าง กำลังบันทึก อ่านอย่างเดียว หรือมี dialog เปิดอยู่
- หมุนล้อเมาส์บนช่องตัวเลขที่กำลัง focus แล้วค่าไม่เปลี่ยน; ช่องที่ต่างจากข้อมูลเปิดล่าสุดมีสีและคำอธิบายสำหรับโปรแกรมอ่านหน้าจอ เมื่อย้อนค่าเป็นเดิมจะยกเลิกเครื่องหมายแก้ไขและค่าค้างของชุดนั้น
- ยอดคงเหลือ PT/NB คำนวณสด: ยกมา + รับใหม่ + รับย้าย − การจำหน่าย 5 ทาง ไม่บวก A&D และไม่แก้ `patientDays` เดิม
- คำเตือนสีเหลืองสำหรับยอดติดลบ เกินเตียง และผลรวมประเภทผู้ป่วยต่างจากยอด PT โดยระบุฐาน PT ชัดเจน ทุกคำเตือนมีปุ่มไปดูช่องและไม่เพิ่มข้อห้ามบันทึก ช่องที่ยังว่างแสดง `—` แทนการอ้างว่าเป็นศูนย์
- แถบบันทึกด้านล่างแสดงยอด PT/NB จำนวนข้อควรตรวจสอบ ข้อมูลที่ยังไม่บันทึก และเวลาเก็บค่าค้าง/บันทึกสำเร็จในหน้านี้ ผ่าน util เวลาไทยกลาง
- เมื่อบันทึกสำเร็จแสดง Toast และทางลัดเวรถัดไป/รอยืนยัน ถ้าไม่มีเวรถัดไปในวันเดียวกัน ให้เลือกวันและเวรเอง ไม่สมมติวันที่ของเวรข้ามคืน
- ถ้าบันทึกไม่สำเร็จ ค่าที่กรอกและค่าค้างยังอยู่ กรณีคู่ข้อมูลรายเดือนไม่ครบจะเปิดส่วนข้อมูลและ focus ช่องที่ว่าง ส่วนข้อขัดแย้งข้อมูลจะ focus ข้อความแจ้ง ไม่เดาว่าช่องใดผิด

## การเก็บค่าค้างและเตือนก่อนออก

ใช้ localStorage เฉพาะยอดนับในแบบฟอร์ม ไม่เก็บ session, CSRF, ชื่อผู้ป่วย หรือผลตอบกลับบริการทั้งก้อน

คีย์แยกตาม `บัญชี / หอ / วัน ISO / เวร primary key / รายการ / version` พร้อม snapshot ค่าเริ่มต้นทั้งหมด รวมข้อมูลรายเดือนและแผลกดทับ การคืนค่าต้องกดเองหลังอ่านข้อมูลปัจจุบันสำเร็จ:

1. บัญชี หอ วัน เวร และเวอร์ชันต้องตรง และยังมีสิทธิ์เขียน/รายการยังไม่ยืนยัน
2. snapshot ต้นฉบับต้องตรงด้วย จึงจับกรณีข้อมูลรายเดือนเปลี่ยนโดย entry version ยังเท่าเดิมได้
3. รับเฉพาะชื่อ field ของฟอร์มและค่าตัวเลข/สตริงตัวเลข/ค่าว่างที่อนุญาต ไม่รับ field แปลกหรือข้อมูลเสีย ใช้กู้คืนได้ภายใน 7 วัน
4. ไม่คืนค่าอัตโนมัติและไม่ส่งเข้าบริการอัตโนมัติ ข้อมูลเก่าที่ไม่ตรงจะมีคำอธิบายและปุ่มลบ ไม่มีปุ่มคืนค่า
5. เก็บหลังแก้ไขในเครื่อง ล้างค่าค้างของบัญชี/บริบทนั้นเมื่อบันทึกสำเร็จ หากเปลี่ยนไปเวรอื่น ค่าค้างเดิมยังอยู่แยกกันเพื่อกลับมาเลือกคืนค่าได้

ก่อนเปลี่ยนหอ/วัน/เวร เปิดแบบฟอร์มใหม่ กดลิงก์ออก หรือออกจากระบบ จะมี shared ConfirmDialog ถ้ายังมีข้อมูลแก้ไข การยกเลิกคงค่าและคืนโฟกัสให้ช่องเดิม รวมวัน พ.ศ. ที่พิมพ์ไว้ การปิด/รีเฟรชหรือออกจากเอกสารใช้คำเตือน beforeunload ของเบราว์เซอร์พร้อมเก็บค่าค้าง

หาก browser ไม่อนุญาตจัดเก็บ จะบอกว่าเก็บไม่ได้โดยไม่อ้างว่าเก็บสำเร็จ และยังบันทึกเข้าระบบได้ตามเดิม ไม่มีคิวส่งซ้ำอัตโนมัติหรือการเปลี่ยนกฎ version conflict

## ข้อมูลที่ใช้ร่วมกับหน้าอื่น

- ส่วนรายเดือนพับได้ทุกขนาด แสดงเดือน พ.ศ. สถานะว่ามีข้อมูลแล้ว/ยังไม่มี/กำลังแก้ไข และคำเตือนว่ามีผลต่อทั้งเดือน
- ใช้ `monthlyLabels` ชุดเดียวกับหน้าตัวชี้วัดเสริมทั้งสองช่อง โดยรักษาความหมายเดิมของ `discharge_count` ไม่เปลี่ยนไปเป็นยอดเดือนอื่น
- ลิงก์ไป `/indicators` ส่งบริบทหอ วัน และเดือนผ่าน query ที่ตรวจสอบก่อนใช้เป็นค่าเริ่มต้น หอจะต้องอยู่ในรายการที่บัญชีอ่านได้ ไม่โหลดหรือบันทึกตัวชี้วัดอัตโนมัติ
- เวรบ่ายมีคำเตือนแผลกดทับเมื่อยังไม่มีข้อมูลส่วนนี้ในบริบท และลิงก์ไปหน้าตัวชี้วัดด้วยบริบทเดียวกัน
- เปลี่ยนเฉพาะค่าเริ่มต้นตามลิงก์และ label ที่ใช้ร่วมในหน้าตัวชี้วัด ไม่เปลี่ยน `loadIndicators`, `loadedKey`, `savePressure`, `saveReadmission` หรือข้อห้ามแก้หลังยืนยัน การปรับหน้าตัวชี้วัดทั้งหน้ายังเป็นเฟส 5

## ข้อมูลส่งและ logic เดิม

ส่วนสร้าง body และคำขอใน `save`, `initialValues` และ `confirmEntry` ตรงกับก่อนเริ่มเฟส 3b ทุกตัวอักษร การเพิ่มหลัง save สำเร็จมีเฉพาะล้างค่าค้าง/เก็บเวลาหน้าจอ คำขออ่านและเขียนของตัวชี้วัดก็ตรงเดิม ดู [หลักฐาน hash](screenshots/phase-3b/protected-source.json)

| กลุ่ม | ก่อน → หลัง |
| --- | --- |
| ช่องหลักรวมเตียง | 29 → 29; ชื่อ field/Number conversion/required/min/max/step เดิม |
| สาขา | 26 → 26 เฉพาะเวรบ่าย; `specialty_code/category_code/count_value` และลำดับ array เดิม |
| แผลกดทับ | 2 → 2 เฉพาะเวรบ่าย |
| รายเดือน | 2 → 2; เงื่อนไขส่ง `readmission/previous_readmission` เดิม รวม null/ไม่ส่งเมื่อไม่เปลี่ยน |
| สร้าง/แก้ไข/ยืนยัน | POST/PATCH/POST เดิม, ISO/primary shift id/expected_version/CSRF/event เดิม |
| สิทธิ์และสถานะ | `can_write`, `is_admin`, confirmed/read-only และการยืนยันเดิม ไม่สร้าง role หรือสถานะเพิ่ม |

จับคำขอก่อนแก้ แล้วกรอกค่าเดียวกันหลังแก้ ผ่าน deep equality 8 กรณี: สร้างดึก/เช้า/บ่าย แก้ไขรายเดือนที่เปลี่ยน/ไม่เปลี่ยน ยืนยัน รายการล็อก และบัญชีอ่านอย่างเดียว รวมตรวจ attributes ของ inputs ไม่ได้เทียบเพียงจำนวน key

หลักฐานข้อมูลสมมติ: [ก่อนแก้](screenshots/phase-3b/request-before.json), [หลังแก้และผลเทียบ](screenshots/phase-3b/request-comparison.json) รายชื่อ field ครบยังดูได้ใน [รายงานเฟส 3a](ui-phase-3a.md)

ไม่เพิ่ม endpoint, dependency, routing, data model, สูตรรายงาน หรือการโหลดแบบฟอร์มอัตโนมัติ ปุ่มเปิดแบบฟอร์มจากเฟส 3a ยังคงอยู่

## การทดสอบ

- `npm run test:ui` ผ่าน **21/21** รวม 6 กรณีใหม่เรื่องแยกคีย์ค่าค้าง ค่า 0/ว่าง ข้อมูลเปลี่ยน/หมดอายุ/ข้อมูลเสีย สูตรยอดและคำเตือน
- Browser ผ่าน **20 กลุ่มตรวจ**: คีย์บอร์ด/กัน submit โดย Enter, wheel, highlight/undo, hotkey ขณะ dialog, validation คู่รายเดือน/โฟกัส, guard เปลี่ยนวัน/เวร/ลิงก์/ออกจากระบบ, refresh/คืนค่า, version conflict, รายเดือนเปลี่ยน, ข้ามบัญชี, อ่านอย่างเดียว, localStorage ใช้ไม่ได้ และหน้าตัวชี้วัดรับบริบทโดยไม่ auto-load
- `/entries` ที่ **360/768/1024/1440px** ไม่มี page overflow ค่าที่กรอกไม่หาย input เวรบ่ายครบ 59 ตัวทุกขนาด; แถบบันทึกและ safe area ใช้ tokens เดิม มีการปรับตาม visualViewport เมื่อคีย์บอร์ดเปิด
- Browser ใช้ Edge headless และ intercept คำขอทั้งหมดด้วยยอดนับสมมติ ไม่มีการอ่านหรือเขียนข้อมูลผู้ป่วยจริง ผลนี้ไม่ใช่ผลทดสอบ backend จริง
- `npm run build` ผ่าน; `npm run lint` ยังไม่มี script เดิม; `npx --no-install tsc --noEmit` ยังไม่มี compiler/config เดิม ไม่ดาวน์โหลดเครื่องมือเพิ่มเอง

ผล browser: [editing-qa.json](screenshots/phase-3b/editing-qa.json) ภาพตรวจยอด/คำเตือน: [360](screenshots/phase-3b/review-360.png), [768](screenshots/phase-3b/review-768.png), [1024](screenshots/phase-3b/review-1024.png), [1440](screenshots/phase-3b/review-1440.png) และภาพโครงฟอร์มอยู่ในโฟลเดอร์เดียวกัน

เก็บชุดตรวจรันซ้ำไว้ที่ `frontend/tests/browser/entry-editing.cjs` เปิด dev server ที่พอร์ต 3000 ก่อน ใช้ Playwright ที่มีอยู่แล้วโดยกำหนด `PLAYWRIGHT_MODULE` เป็นพาธโมดูลนั้นหากไม่ได้อยู่ใน node_modules แล้วรัน `node tests/browser/entry-editing.cjs` จาก frontend ไม่ได้เพิ่ม Playwright เป็น dependency ของโปรเจกต์
