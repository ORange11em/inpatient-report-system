# เฟส 7 — QA ตามเกณฑ์ตรวจรับ

ตรวจวันที่ 20 พฤศจิกายน 2569 · **ตรวจอย่างเดียว ยังไม่แก้โค้ด**

ผลรวมในขอบเขตเบราว์เซอร์ทดสอบ: **ผ่าน 5/7 ข้อ ไม่ผ่าน 2/7 ข้อ** จึงยังไม่ปิดการตรวจรับทั้งระบบ พบรายการแก้ 5 รายการด้านข้อความ/contrast/ขนาดปุ่ม/Toast และยังต้องตรวจ Lighthouse กับอุปกรณ์จริงตามขั้นตอนท้ายรายงาน

## สิ่งที่ตรวจจริงและหลักฐาน

- **โค้ด/ข้อมูลส่ง:** ตรวจ routes, components ที่เกี่ยวข้อง และข้อความ error; snapshot SHA-256 ก่อน/หลังยืนยันไม่มีการแก้ไฟล์โค้ดหรือการเรียกข้อมูล
- **หน้าจอ:** 8 มุมมอง × 7 ความกว้าง = 56 กรณี เพิ่มแนวนอน 1024×768 อีก 8 กรณี รวม **64 measurements** ไม่พบ page overflow หรือ ISO ในเนื้อหาที่ตรวจ
- **จุดเปลี่ยนเมนู:** 767px = bottom nav; 768/1023px = rail 80px; 1024px = sidebar 248px สลับถูกต้อง
- **คีย์บอร์ด:** กรอกจริง 59 ช่องที่ 1440/360 ด้วย key events ไม่ใช้ pointer เพื่อกรอก ตรวจ body ครบและบันทึกสำเร็จในบริการจำลอง
- **Regression:** history 16 กลุ่ม, indicators 18, entry-editing 20, reports 18 รวม **72 กลุ่ม** ผ่านทั้งหมด; ทุก suite ดักบริการก่อนเปิดหน้า
- **รายงาน/ส่งออก:** GET parameter contracts เดิมครบ 15 ชนิดตรงเดิม ไฟล์ XML 15 ชนิดชื่อ พ.ศ. ตัวเลขและชนิด Number ตรงเดิม ไม่เปลี่ยน null เป็น 0
- **Print:** รัน browser print ใหม่ ตรวจขนาด/หัวซ้ำ/แถวครบ/ข้อความไม่ล้นใน PDF 31+3 หน้า และดูภาพซ้ำ; ไม่ใช่การตรวจเครื่องพิมพ์จริง
- **Contrast:** ใช้ relative luminance จากสี computed ที่ประกอบ alpha แล้ว ข้าม gradient ที่ยังระบุพื้นหลังแน่นอนไม่ได้ ไม่ใช้ผลนี้แทน Lighthouse/การตรวจทุกสภาวะ

## วิธีทดสอบบนหน้าจอ/อุปกรณ์จริงให้เจ้าของงาน

ใช้บัญชีและหอทดสอบในระบบทดสอบ เก็บ URL, รุ่นอุปกรณ์/OS/browser, ขนาด viewport/zoom, วันเวลา และภาพหรือวิดีโอเมื่อไม่ผ่าน ไฟล์ใน `screenshots/phase-7/` ที่มีอยู่เป็นข้อมูลสมมติ

### M01 — Zoom 200%, สระไทย และ responsive ใน browser จริง

1. เปิดทั้ง 8 มุมมองจากตารางด้วย Chrome/Edge บนจอคอม ตั้ง zoom ผ่านเมนู browser เป็น **200%** (การย่อ viewport ในเครื่องมือจำลองไม่แทนการตรวจนี้)
2. ไล่หัวหน้า label ข้อความ error ตาราง/dialog และปุ่มท้ายฟอร์ม ต้องไม่ตัดสระ/วรรณยุกต์หรือซ้อนกัน เลื่อนแนวนอนได้เฉพาะในกรอบตาราง
3. เปิด/ปิดเมนู ตัวกรอง ปฏิทิน รายละเอียดประวัติ เปลี่ยนแนวหน้าจอ และ resize ผ่าน 767/768 กับ 1023/1024px ตรวจว่าไม่มีเมนูสองแบบซ้อนหรือ overlay ค้าง
4. บันทึกผลผ่าน/ไม่ผ่านแยกแต่ละหน้า พร้อมภาพของสิ่งที่อ่าน/กดไม่ได้ แล้วคืน zoom 100%

### M02 — iPhone Safari / Android Chrome และแป้นพิมพ์จริง

1. เปิด URL ระบบทดสอบที่มือถือเข้าถึงได้ เลือกหอ/วัน/เวรบ่ายที่ยังไม่ยืนยัน ทดสอบหน้าจอใกล้ **360px** และเครื่องที่มี safe area ถ้ามี
2. แตะช่องแรกเพื่อเปิดแป้นพิมพ์ กรอกจำนวนและเลื่อนผ่านส่วนผู้ป่วย/เจ้าหน้าที่/สาขา/แผลกดทับ/รายเดือน เปิดส่วนพับและเลื่อนไปสองช่องท้าย ตรวจช่องที่ focus มองเห็นและปุ่มไม่ทับคีย์บอร์ด
3. หมุนแนวตั้ง–แนวนอน พับ/เปิดแป้นพิมพ์ เข้าโหมดกรอกเต็มจอและออก ค่าต้องไม่หาย แถบปุ่มไม่ทับ bottom nav หรือปุ่มระบบ
4. บันทึก ตรวจข้อความสำเร็จ แล้วลองแตะปุ่มบันทึกอีกครั้ง **F05 ทำซ้ำได้ในจอจำลอง: Toast บังปุ่ม** ให้ตรวจซ้ำหลังแก้และบันทึกภาพไว้ ไม่กดข้ามข้อความที่ไม่เข้าใจ
5. เปิดหน้ารายงาน ตัวกรอง และการ์ดครองเตียง เปิดครบ 12 เดือน/สลับตาราง ตรวจการแตะคำอธิบายบนจำนวนเวร และปิด overlay ได้

### M03 — คีย์บอร์ดจริงและโปรแกรมอ่านหน้าจอ

1. บนคอม วางเมาส์ไว้แล้วใช้ Tab/Shift+Tab, Enter/Shift+Enter กรอกเวรบ่ายครบ 59 ช่อง รวมวันที่/เดือนด้วย พิมพ์เตียงอย่างน้อย 1 และค่าจำนวนเต็มที่ถูกต้อง แล้ว Ctrl+S หรือ Cmd+S ยืนยัน dialog ด้วย Enter
2. ใช้คีย์บอร์ดเปิด sidebar/drawer, ตัวกรอง, ปฏิทิน, รายละเอียด, ยืนยัน/ส่งกลับ ทดสอบ Tab ไม่หลุด dialog, Esc ปิด และ focus กลับปุ่มเดิม
3. ใช้ NVDA+Chrome หรือ VoiceOver+Safari อ่านชื่อช่อง เช่น “รับใหม่ PT”, สถานะ ยอด และข้อความบันทึก/ผิดพลาด ต้องรู้ความหมายโดยไม่ใช้สีเพียงอย่างเดียว
4. เก็บชื่อช่อง/ปุ่มที่อ่านซ้ำ ไม่มีชื่อ หรือไม่เห็น focus โดยเฉพาะ login หลังแก้ F03 ข้อนี้ยังไม่ได้ทดสอบด้วย screen reader จริง

### M04 — Lighthouse Accessibility ≥95 ทุกหน้า

1. ใน Chrome ใช้บัญชีทดสอบ เปิดหน้าเป้าหมายให้มีข้อมูล รอโหลดเสร็จ เปิด DevTools → **Lighthouse** เลือก Accessibility และทดสอบ Mobile/Desktop
2. รัน audit การโหลดหน้า ถ้าล้าง storage แล้ว session หาย ให้ตั้งค่ารักษา session ที่เวอร์ชันนั้นรองรับและตรวจ URL สุดท้าย ต้องเป็นหน้าที่ตั้งใจตรวจ ไม่ใช่หน้า login หลัง redirect
3. ทำครบทั้ง 8 มุมมอง ฟอร์มใช้ลิงก์หอ/วัน/เวรทดสอบที่เปิดฟอร์มได้ทันที เก็บ HTML/JSON รายงาน พร้อม browser/version/mode/viewport
4. **ทุกหน้าต้อง ≥95 แยกกัน ไม่ใช้ค่าเฉลี่ย** ถ้าต่ำกว่าให้แนบ failed audits/element selectors เพื่อระบุไฟล์ที่จะต้องแก้เพิ่ม
5. ตรวจด้วยสายตา/คีย์บอร์ดตาม M01–M03 ต่อด้วย คะแนนไม่ได้แทนผล contrast ของขอบ input หรือ manual audits ทั้งหมด

อ้างอิงขั้นตอน [Chrome Lighthouse](https://developer.chrome.com/docs/lighthouse/overview/) และข้อจำกัดของคะแนน [Accessibility scoring](https://developer.chrome.com/docs/lighthouse/accessibility/scoring/) ยังไม่ได้รัน CLI เพราะไม่มีเครื่องมือในโปรเจกต์/ชุด runtime และไม่ได้เพิ่มแพ็กเกจหรือแต่งคะแนนขึ้นมา

### M05 — หน้าพิมพ์และเครื่องพิมพ์จริง

1. เปิดรายงานรายวันหลายหอและอัตราการครองเตียง ใช้ “พิมพ์” เลือก **A4 แนวนอน** ตรวจทุกหน้าใน preview และพิมพ์ขาวดำอย่างน้อยหน้าแรก/กลาง/ท้ายของแต่ละงาน
2. ปิด **Headers and footers ของ browser** เพื่อไม่ให้ URL หรือวัน ค.ศ. จาก browser แทรก หัวพิมพ์ของระบบมีโรงพยาบาล/รายงาน/เงื่อนไข/ผู้พิมพ์/วัน พ.ศ. อยู่แล้ว
3. ตรวจหัวตารางซ้ำ แถวไม่ขาดกลางหน้า ชุดคอลัมน์รายวันมีหอ/วัน/เวรทวนครบ เดือน/เฉลี่ยปี/ส่วนต่างครองเตียงไม่ตกขอบ สระและเส้นตารางอ่านได้ และไม่มีหน้าว่างแทรก
4. บันทึกรุ่นเครื่องพิมพ์/driver/scale/margins หากต่างจาก PDF ตัวอย่าง ไม่รับรองการพิมพ์จริงจาก PDF อัตโนมัติเพียงอย่างเดียว

### M06 — เปิด Excel XML ใน Microsoft Excel จริง

1. ดาวน์โหลดรายวัน รายปีงบ รายงานช่วงเดือน และครองเตียง ชื่อไฟล์ต้องเป็น พ.ศ. เช่น `อัตราการครองเตียง_ปีงบ2570.xml` ไม่เปลี่ยนชื่อเป็น .xlsx
2. เปิดด้วย Microsoft Excel ตรวจข้อความไทย ชื่อเดือน/วันที่ และดูว่าไม่มีหน้าต่างซ่อมไฟล์ เก็บภาพถ้ามีการแจ้งเตือนผิดรูปแบบ
3. เลือกเซลล์ตัวเลขแล้วดู formula bar ค่าต้องตรงรายงานต้นฉบับ เช่นทศนิยมเดิมยังอยู่ แม้หน้าจอปัดแสดง 1 ตำแหน่ง ลอง SUM กับตัวเลขสำเนาทดสอบได้ ค่าว่างไม่กลายเป็น 0
4. ตรวจศูนย์จริง ข้อมูลไม่ครบที่แสดงจำนวนเวร และค่าเฉลี่ยรวมเดิม ไม่รวมยอดหรือเฉลี่ยใหม่เพื่อให้ตรงความคาดหมาย

### M07 — เชื่อมบริการจริง/สิทธิ์/ข้อมูลชนกันในระบบทดสอบ

1. ทดสอบบัญชีผู้บันทึก/อ่านอย่างเดียว/ผู้ดูแลที่มีอยู่จริง ไม่อนุมานว่าชื่อ HN เป็น role หัวหน้าหอ ทดสอบปุ่มแก้ไขจากประวัติแล้วได้หอ/วัน/เวรเดิม
2. เปิดรายการเดียวกันสองหน้าต่าง บันทึก/ยืนยันจากอีกหน้าต่าง แล้วลองบันทึกจากหน้าต่างเก่า ต้องแจ้งข้อมูลเปลี่ยนและไม่เขียนทับโดยข้าม version
3. ตรวจเวรบ่ายยืนยันแล้วแผลกดทับอ่านอย่างเดียว การแก้รายเดือนสะท้อนในหน้าประจำวันและตัวชี้วัด ค่าค้างบัญชีหนึ่งไม่คืนให้บัญชีอื่น และ error/retry ไม่ส่งซ้ำเอง
4. ผลชุดทดสอบครั้งนี้ยืนยัน frontend และคำขอที่ดักไว้เท่านั้น ต้องตรวจผลบริการจริงก่อนรับรองการใช้งาน
